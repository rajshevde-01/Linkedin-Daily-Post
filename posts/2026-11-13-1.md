**✅ WEEK IN REVIEW — MAJOR BREACHES**  

Last week, **FinBank** fell victim to a credential‑theft campaign that leveraged the newly disclosed **CVE‑2026‑0801** in the serverless runtime used for its transaction micro‑services. Attackers sent a spear‑phishing email that spoofed an internal HR portal, achieving a **68 %** click‑through rate among targeted employees. Within minutes, a compromised Lambda function harvested API keys, pivoted to the **S3** data lake, and exfiltrated **4.2 million** records. The human element, not the code, was the weakest link.

**⚠️ TECHNICAL RADIANCE**  

[SYSTEM ANALYSIS]  
- **Lambda** functions ran with **full‑access IAM** roles – a classic privilege‑escalation misconfiguration.  
- The exploit chain used **CVE‑2026‑0801** to bypass the runtime sandbox, allowing arbitrary code execution.  

[THE EXPLOIT]  
- Phishing email → compromised credentials → stolen **AWS_ACCESS_KEY_ID** → Lambda injection → data dump.  
- Attackers leveraged an OAuth token refresh flow that **MFA** could not stop because the token was already minted.  

[RECOMMENDED REMEDIATION]  
- Enforce **least‑privilege IAM** policies for every serverless component.  
- Rotate all **API keys** immediately and enable **conditional access** based on device posture.  
- Deploy a **behavior‑based SOAR**
